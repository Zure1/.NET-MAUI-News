# .NET MAUI News — July 2026

**Date range covered:** 1–31 July 2026  
**Signal level:** High — stable MAUI servicing and the .NET 11 runtime and framework changes need focused regression testing.

## Key updates

This month was mostly about **stable servicing, CoreCLR becoming mandatory for .NET 11 mobile apps, framework architecture changes, and build-tool reliability**.

| Area | Update |
|---|---|
| Stable MAUI | .NET MAUI 10.0.90 shipped with 231 commits and a broad reliability pass. |
| .NET 11 runtime | Preview 6 makes CoreCLR the only runtime for MAUI Android, iOS, and Mac Catalyst apps. |
| Framework changes | CollectionView2 reached Windows, Android Shell moved to handlers, and the compatibility package was removed. |
| AOT and platforms | HybridWebView became AOT-safe; Android and Apple workloads received behavior and packaging changes. |
| Community Toolkit | CommunityToolkit.Maui 15.0.0 prepares Toolkit-based apps for .NET 11. |
| Servicing and tooling | July .NET security updates and Rider 2026.2 require build-image and deployment validation. |

## .NET MAUI 10.0.90 stable servicing

**What changed**

- .NET MAUI 10.0.90 was released on 22 July with 231 commits across controls, navigation, accessibility, memory use, and platform behavior.
- Notable fixes include grouped `CollectionView` leaks, `CollectionView.SelectedItems` retaining popped views, Android `BlazorWebView` back-button handling, and Windows `Border` accessibility support.
- The release also includes fixes for buttons, borders, layouts, lifecycle behavior, and cross-platform rendering regressions.

**Recommended action**

- Update the MAUI workload and package set in a staging branch.
- Test list-heavy screens, grouped collections, navigation stacks, Android back behavior, dynamic resources, accessibility, and memory after repeated page navigation.
- Rebuild and smoke-test Android AAB/APK, Apple archives, Mac Catalyst packages, and Windows MSIX artifacts before changing the production baseline.

**Source link**

- [.NET MAUI 10.0.90 release notes](https://github.com/dotnet/maui/releases/tag/10.0.90)

## .NET 11 Preview 6 makes CoreCLR mandatory on mobile

**What changed**

- `net11.0-android`, `net11.0-ios`, and `net11.0-maccatalyst` now use CoreCLR only. The previous Mono-selection property has been removed.
- Microsoft reports that iOS and Mac Catalyst are generally faster than Mono, while Android startup and app size are currently within about 10% of Mono.
- On-device `dotnet-trace` and `dotnet-counters` are available. Debugging and Hot Reload work, but XAML Hot Reload and some iOS paths still have preview limitations.
- Android NativeAOT work now includes a trimmable Android interop type map.

**Recommended action**

- Create a .NET 11 Preview 6 validation branch; there is no Mono fallback for these mobile targets.
- Compare cold and warm startup, package size, working set, GC behavior, native interop, reflection-heavy libraries, trimming, AOT, diagnostics, and crash reporting against the .NET 10 baseline.
- Test production flows on physical devices, not only templates or emulators.

**Source link**

- [CoreCLR progress and the Mono timeline for .NET MAUI](https://devblogs.microsoft.com/dotnet/coreclr-progress-and-mono-timeline-dotnet-maui/)

## .NET MAUI in .NET 11 Preview 6

**What changed**

- CollectionView2 now has a Windows handler based on WinUI `ItemsRepeater`, including grouping, selection, snapping, incremental loading, headers, footers, empty views, and `RefreshView` support.
- Android Shell now uses MAUI handlers instead of the legacy Shell renderer architecture. This change is Android-only in Preview 6.
- `Microsoft.Maui.Controls.Compatibility` is no longer built or shipped. Projects with an explicit package reference or compatibility renderers must migrate before .NET 11.
- `HybridWebView` JavaScript interop now uses source generation, removing reflection-based trim and AOT warnings. Android also filters message events by source.
- Android adds opt-in `MediaPicker` result recovery after process recreation, and foreground geolocation adds a `MinimumDistance` filter.
- `AndroidMessageHandler` now reports transport failures as `HttpRequestException` and cancellation as `OperationCanceledException`.
- Apple workloads now support stable Xcode 26.6, `.icon` app-icon folders, and automatic builds for referenced app-extension projects.

**Recommended action**

- Regression-test Android Shell navigation and Windows CollectionView behavior with real application data and templates.
- Remove explicit `Microsoft.Maui.Controls.Compatibility` references and migrate custom renderers that depend on it.
- Review Android HTTP exception handling and cancellation tests for the new exception types.
- Use the MediaPicker recovery APIs where losing a captured photo or video would be costly.
- Pin Xcode 26.6 in CI and verify app-extension builds, signing, icons, archives, and store packaging.

## CommunityToolkit.Maui 15.0.0

**What changed**

- CommunityToolkit.Maui 15.0.0 was released on 24 July to prepare for .NET 11.
- The Toolkit removed its use of internal .NET MAUI APIs because those APIs will no longer be accessible in .NET 11.
- The maintainers state that Toolkit 14.2.2 and earlier will not be compatible with .NET 11.

**Recommended action**

- Upgrade to CommunityToolkit.Maui 15.0.0 or later before starting .NET 11 migration testing.
- Regression-test popups, behaviors, converters, DrawingView, and custom extensions that interact with Toolkit controls.
- Upgrade the Toolkit and MAUI workload in the same compatibility matrix rather than testing them independently.

**Source link**

- [CommunityToolkit.Maui 15.0.0 release notes](https://github.com/CommunityToolkit/Maui/releases/tag/15.0.0)

## July .NET SDK and runtime servicing

**What changed**

- Microsoft released .NET 10.0.10, 9.0.18, and 8.0.29 on 14 July.
- The servicing update includes security and non-security fixes and lists 17 corrected .NET security vulnerabilities affecting .NET 10, .NET 9, and .NET 8.
- Updated installers, binaries, container images, and Linux packages were published.

**Recommended action**

- Patch developer machines, hosted and self-hosted CI agents, container images, and signing or release machines.
- Pin the intended SDK with `global.json` and record the resolved MAUI workload set in build diagnostics.
- Rebuild signed artifacts and rerun trimming, AOT, notarization, MSIX, and store-upload smoke tests after updating the toolchain.

**Source link**

- [.NET and .NET Framework July 2026 servicing updates](https://devblogs.microsoft.com/dotnet/dotnet-and-dotnet-framework-july-2026-servicing-updates/)

## Rider 2026.2 MAUI fixes

**What changed**

- Rider 2026.2 was released on 22 July with several fixes directly affecting MAUI build and deployment workflows.
- The release notes include fixes for .NET 10 MAUI Android Release builds crashing because of missing symbols, broken MAUI code signing, APK path and solution-build failures, Android deployment and device-launch problems, and missing Mac-agent controls.
- It also includes a fix for XAML Hot Reload on Android and iOS emulators and physical devices.

**Recommended action**

- Pilot Rider 2026.2 on one development environment before broad rollout.
- Revalidate Android Release launch, iOS remote builds, code signing, device deployment, APK/AAB discovery, and XAML Hot Reload.
- Keep the previous Rider version available until project loading, build, signing, and device tests pass for the team’s supported targets.

## .NET MAUI 10.0.80 stable servicing

**What changed**

- Released June 24 with 112 commits across quality, performance, and developer experience.
- CollectionView and CarouselView received fixes for spacing, scrolling, empty states, headers, footers, and event behavior.
- Platform fixes included Windows password Entry crashes, Mac Catalyst DatePicker events, Android Material 3 dialogs, and Android HybridWebView message-source filtering.
- Controls affected include Button, Entry, Editor, DatePicker, TimePicker, Flyout/FlyoutPage, GraphicsView, and dialogs.

**Recommended action**

- Prefer 10.0.80 over earlier June patches unless a verified regression blocks the upgrade.
- Run UI regression tests around lists, carousel events, Shell/navigation, forms, dialogs, and HybridWebView.
- Rebuild and smoke-test Android, Apple, and MSIX release artifacts.

**Source link**

- [.NET MAUI 10.0.80 release notes](https://github.com/dotnet/maui/releases/tag/10.0.80)

## .NET MAUI 10.0.71 regression patch

**What changed**

- Released June 10 as a narrow follow-up to 10.0.70.
- Fixed or reverted regressions involving Windows WebView/HybridWebView blank rendering, Windows FontImageSource centering, iOS Shell modal keyboard layout, Android bottom navigation, SafeArea listeners, and Shell navigation lifecycle.
- Included MapPool retention work for iOS and Mac Catalyst.

**Recommended action**

- Treat 10.0.71 as useful bisecting context; use 10.0.80 as the normal June baseline.
- If your app passed through 10.0.70 or 10.0.71, retest WebView, Shell modal flows, Maps, icons, and Android tabs.

**Source link**

- [.NET MAUI 10.0.71 release notes](https://github.com/dotnet/maui/releases/tag/10.0.71)

## .NET 11 Preview 5 and MAUI platform changes

**What changed**

- Reliability fixes covered CollectionView, CarouselView, Shell, gestures, layout/RTL, HybridWebView, input controls, navigation lifecycle, and templates.
- Animation APIs such as `FadeToAsync`, `RotateToAsync`, `TranslateToAsync`, `ScaleToAsync`, and `LayoutToAsync` gained `CancellationToken` support.
- `BoxView.Fill` now accepts `Brush`; Windows Map gained a WinUI/Azure Maps implementation.
- .NET 11 MAUI raises the Android minimum to API 24. Android 17/API 37 support stabilized, with `net11.0-android37` as the default target.
- Android trimmable typemap work advanced for CoreCLR and NativeAOT; Apple workloads refreshed Xcode 26.5 bindings and dev-loop builds.

**Recommended action**

- Keep .NET 11 validation outside production branches and pin SDK/workload versions in CI.
- Audit Android minimum-version assumptions and test API 24 plus API 37 devices/emulators.
- Measure startup, package size, memory, trimming, AOT, diagnostics, and crash reporting separately on Android and Apple targets.
- For Windows Maps, validate Azure Maps configuration and feature parity before migration.

**Source links**

- [.NET 11 Preview 5 announcement](https://devblogs.microsoft.com/dotnet/dotnet-11-preview-5/)
- [.NET MAUI Preview 5 release notes](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/preview5/dotnetmaui.md)
- [MAUI Preview 5 GitHub release](https://github.com/dotnet/maui/releases/tag/11.0.0-preview.5.26304.4)

## .NET 8 and .NET 9 support deadline

**What changed**

- Microsoft confirmed that .NET 8 and .NET 9 both reach end of support on November 10, 2026.
- After that date they no longer receive security fixes, servicing, or technical support; .NET 10 LTS is the supported migration target.

**Recommended action**

- Inventory MAUI apps still targeting `net8.0-*` or `net9.0-*`.
- Schedule migration to .NET 10 with explicit validation of workloads, dependencies, signing, MSIX, and mobile-store pipelines.

**Source link**

- [.NET 8 and .NET 9 end-of-support notice](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/)

## SkiaSharp 4.148.0 stable

**What changed**

- The first stable SkiaSharp v4 release shipped on June 22, based on Skia m148.
- It added variable-font color palettes, animated WebP encoding, and zero-copy stream/shaper APIs.
- This is a breaking release: deprecated `SKPaint` text/font APIs became build errors, with further legacy APIs producing warnings.

**Recommended action**

- Test the upgrade in a branch if the app or any charting, mapping, signature, image-processing, or PDF library uses SkiaSharp.
- Review API diffs, transitive version constraints, graphics output, native asset packaging, startup, and memory on every target.

**Source link**

- [SkiaSharp 4.148.0 release notes](https://mono.github.io/SkiaSharp/docs/releases/4.148.0.html)

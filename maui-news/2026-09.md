# .NET MAUI News — September 2026

**Date range covered:** 01. 09 → 30. 09  
**Signal level:** High — stable servicing, .NET 11 RC1, and build-toolchain changes all landed this month.

## Key updates

This month was mostly about **.NET 10 servicing, .NET 11 release-candidate validation, cross-platform regression fixes, and build-toolchain readiness**.

| Area | Update |
|---|---|
| Stable MAUI | .NET MAUI 10.0.110 shipped on September 22 and is the current supported servicing level. |

## 1. .NET MAUI 10.0.110 is the current stable servicing level

### What changed

.NET MAUI 10.0.110 shipped on **September 22, 2026**. Microsoft's MAUI support policy now lists 10.0.110 as the latest .NET MAUI 10 patch. Microsoft requires customers seeking technical support to be on the latest servicing level.

### Recommended action

Move production .NET MAUI 10 applications to 10.0.110 after normal regression testing. Pay particular attention to platform-specific UI, navigation, lifecycle, packaging, and custom-handler behavior when upgrading from older servicing builds.

### Source link

- https://dotnet.microsoft.com/en-us/platform/support/policy/maui
- https://github.com/dotnet/maui/releases

## 2. .NET 11 RC1 and .NET MAUI 11 RC1 are available

### What changed

.NET 11 RC1 shipped on **September 8, 2026** with a go-live support license. The corresponding .NET MAUI 11 RC1 workload is available as `11.0.100-rc.1.26458.5`. MAUI's RC1 release contains hundreds of commits focused on quality, performance, platform behavior, and developer experience.

This is also the first release-candidate phase after the .NET 11 MAUI runtime transition to CoreCLR on Android, iOS, and Mac Catalyst.

### Recommended action

Start final .NET 11 migration testing now if a MAUI 11 upgrade is planned near GA. Test startup, trimming/AOT, native interop, app lifecycle, custom handlers, third-party controls, iOS/Mac Catalyst builds, and Android release builds rather than limiting validation to debug builds.

### Source link

- https://devblogs.microsoft.com/dotnet/dotnet-11-rc-1/
- https://github.com/dotnet/maui/releases
- https://learn.microsoft.com/dotnet/maui/whats-new/dotnet-11

## 3. September servicing fixed several cross-platform regressions

### What changed

The September MAUI servicing work included targeted fixes across the major platforms. The 10.0.101 release on September 7 included fixes for Android Material 3 status-bar readability, Android media-picker completion, Android root-page back handling, iOS safe-area behavior, an iOS button-style regression, and Windows dynamic content assignment.

Repository activity immediately after the release also included fixes for a Windows `TabbedPage` back-navigation crash, Android locale-aware decimal input, Material 3 picker styling, and a `GradientBrush` memory leak.

### Recommended action

If your app stayed on an older .NET MAUI 10 servicing build because of one of these regressions, retest against 10.0.110. Add regression tests for navigation, safe areas, system chrome, media capture, localized numeric input, and long-running UI scenarios where practical.

### Source link

- https://github.com/dotnet/maui/releases
- https://github.com/dotnet/maui/issues/38309

## 4. Android CI provisioning is moving toward Microsoft.Maui.Cli

### What changed

MAUI repository infrastructure replaced `androidsdk.tool` with `Microsoft.Maui.Cli` for Android SDK, JDK, and emulator provisioning. The change is aimed at making Android CI setup more repeatable and aligning provisioning with MAUI-owned tooling.

### Recommended action

Teams maintaining custom MAUI Android CI bootstrap scripts should watch `Microsoft.Maui.Cli` and compare it with their existing SDK/JDK/emulator setup. Keep stable production pipelines unless the CLI covers your requirements and passes your validation.

### Source link

- https://github.com/dotnet/maui/issues/38265

## 5. Microsoft's NuGet author-signing certificate changed

### What changed

Starting **September 23, 2026**, Microsoft began using a new author-signing certificate for NuGet packages. Normal NuGet restores are unaffected, but MAUI build environments with explicit package-signature verification may need their accepted Microsoft certificate list updated.

### Recommended action

Check MAUI CI agents, developer-machine NuGet configuration, internal package proxies, and package-verification scripts. If Microsoft certificates are explicitly pinned, follow Microsoft's migration instructions and test package restore on the actual build agents.

### Source link

- https://devblogs.microsoft.com/dotnet/microsoft-author-signing-certificate-update-2026/
